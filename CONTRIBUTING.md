# Contributing

Use Node 24 and npm ci. Keep changes scoped, accessible, strictly typed and documented. Run npm run verify and (after installing Chromium) npm run test:e2e before opening a PR. Add meaningful tests for behavior and error boundaries, not test-count padding.

Never commit secrets or generated output. Keep external providers behind explicit adapters. Do not implement planned product systems during Phase 0. Record significant architectural decisions as ADRs. Describe behavior, verification and limitations in your PR. Contributions are licensed under Apache 2.0.

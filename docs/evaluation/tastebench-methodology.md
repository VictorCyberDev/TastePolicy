# TasteBench methodology v1

Predeclared in [ADR 0008](../decisions/0008-tastebench-methodology.md) before results. Schema/validation contracts are [versioned with the data](../../benchmarks/tastebench/v1/schemas/contracts.md). Implementation: benchmarks/tastebench/lib. This document is an interpretation guide, not post-hoc metric selection.

| Metric                 | Numerator / denominator and interpretation                                                                                                                                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Human policy agreement | Exact predicted/target match / all scorable human targets, including unavailable/invalid executions as nonmatches. Explicit excluded/unlabeled/unscorable/unadjudicated counts.                                                                              |
| Unsafe autonomy        | ALLOW when target ASK/REJECT / scorable human targets; also total ALLOW predictions. Not a universal safety claim.                                                                                                                                           |
| Excessive ASK          | ASK when target ALLOW / scorable human targets. ASK versus REJECT remains a separate matrix cell.                                                                                                                                                            |
| Confusion              | Counts for every 3×3 valid target/prediction pair, with UNAVAILABLE/INVALID_OUTPUT separately exposed.                                                                                                                                                       |
| Contract compliance    | Matched mechanically registered outcomes / system-eligible engineering expectations. Not human accuracy.                                                                                                                                                     |
| UNAVAILABLE / invalid  | Each count / executed scenarios, typed unavailable reason histogram; never coerce either to REJECT/ASK.                                                                                                                                                      |
| Replay                 | Mismatch count / two comparisons after first deterministic execution (three identical-input executions total). Compare semantic outcome, basis/reasons, actual receipt fields, system/version/input hashes.                                                  |
| Stability              | Exact registered expected outcome matches / eligible named perturbations. Price below/equal/above max and cultural score boundaries; not provider confidence.                                                                                                |
| Feedback               | Later specified-state outcome matches / eligible registered before/event/after transitions. Human preference improvement not inferred.                                                                                                                       |
| Interaction            | Plan/factor/answer or bounded repair behavior matches / registered interactions. First prediction stays separate.                                                                                                                                            |
| Receipt completeness   | Fully present existing required fields / eligible available cultural evaluations. Required fields are exported as RECEIPT_FIELDS; missing receipt counts as missing fields, not excluded success. No fake receipt for unavailable or independent hard block. |
| Provider calls         | Actual wrapped method total/average/max; synthetic operation histogram separate from zero-call offline policy and externally declared model counts. No live HTTP in default run.                                                                             |
| Latency                | Sample count/min/median/max, nearest-rank p95 only n>=20. Separate offline policy, synthetic SQL/provider interaction and externally supplied model timings. No misleading speed comparison.                                                                 |

Human records are optional genuine external inputs; no code-generated ground truth. Single annotations and explicit adjudication are separate. Pairwise raw human agreement counts distinct annotator pairs with scorable labels; no kappa or significance. Contract fixtures are never accepted as human cases. Human annotation packets omit Qloo scores and every system decision. Calibration and held-out metrics are separate; calibration analysis accepts only filtered calibration packets and rejects contaminated packets.

Dataset manifests bind scenario hashes, sorted split assignment, annotation/metric versions and domain/source distributions. Both ID and content duplicates fail, including renamed cross-split copies. Content hashes omit administrative scenario ID/split/oracle; full record/dataset hashes retain them. No exclusions are silently introduced: malformed input fails the dataset, incomplete external coverage fails import, malformed attributable response stays INVALID_OUTPUT. All current runs have zero scenario exclusions.

Canonical sorted serialization and SHA-256 bind semantic inputs/predictions/results/metrics. Timing and random run/request/receipt IDs are excluded only from semantic reproduction; raw artifact hashes also bind actual timings. Run manifests record code SHA/dirty state, Node version, prompts/system versions, environment blocks, dataset/annotation hashes and evidence mode. Reports recompute metrics from raw records, reject mismatched hashes/counts, and verify deterministic predictions against accepted services. Hashes detect inconsistency; they are not signatures or proof of provider/human authenticity.

CAPTURED/SYNTHETIC contract execution is the initial mode; fresh live benchmark mode is not implemented and no live provider is called. No human or LLM run means no human-agreement or comparative-win claim. No composite TasteScore, p-value, significance, confidence interval or population generalization. Production thresholds remain >0.80 / 0.50–0.80 inclusive / <0.50. Any future production calibration requires separate authorization; M4 is outside scope.

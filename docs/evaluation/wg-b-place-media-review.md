# WG-B licensed place media review

Reviewed starting head: `8d089fd1ed0cdaa8b5f9331c8e6b1f1cf68e0c53`.

The seven existing Wikimedia presentation commits are preserved. Review identified unvalidated external URLs, overly broad license-prefix acceptance, substring relevance matching, absent classification/query provenance, and a previous-candidate photo remaining during the next request. The original commits added no focused media regressions.

The existing `/api/media/place` route still performs one bounded Commons search (eight results, 4.5-second request/body deadline). It searches the quoted candidate-name phrase and uses the address for local disambiguation; live review found that including every street/postcode token suppressed the otherwise available HOTEL CYCLE context image. It refuses upstream redirects. Media, file-page and license URLs are validated separately. Images must use HTTPS `upload.wikimedia.org` or `thumb.wikimedia.org` under `/wikipedia/commons/`; known first-party thumbnail tracking parameters are removed. Other queries, fragments, credentials, unexpected hosts and schemes fail closed. File links must use HTTPS `commons.wikimedia.org/wiki/File:`. The license identifier must agree with a canonical HTTPS Creative Commons license URL.

Accepted licenses are explicitly CC BY and CC BY-SA (1.0, 2.0, 2.5, 3.0, 4.0), CC0 1.0 and the Public Domain Mark 1.0. Other licenses and missing creator credit are unavailable. This intentionally conservative subset may reject reusable media. Commons metadata is attribution evidence, not an independent legal warranty. See [Commons reuse guidance](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia) and [Imageinfo contract](https://www.mediawiki.org/wiki/API:Imageinfo).

All distinctive name tokens must occur as whole tokens. Single-token names additionally require the full candidate-name phrase, a location token and a minimum token length. Name/address text is used only for media search and disambiguation. This heuristic cannot independently verify a property. Every accepted image is therefore `LOCATION_CONTEXT`, captioned “Licensed visual context — exact property not verified.” No `EXACT_PLACE` result is issued. Server failure/no acceptable match is `UNAVAILABLE`; the existing local portrait is the `GENERIC_MOOD` presentation fallback, labeled “Visual mood artwork — presentation only.”

Available responses include source, exact search query, `presentationOnly: true`, classification, title, creator, image URL, license and license/file-page links. Creator and license links remain visible after successful image load; cropping is disclosed. A photo is hidden until load completes. Load failure, provider failure and candidate changes restore the local portrait. Late responses cannot attach to another candidate. No extra imagery request occurs in the evaluator.

Qloo remains cultural evidence. Commons remains presentation photography. TastePolicy remains authorization and bounded continuation. No image data is added to Qloo evidence or Cultural Receipt. No provider, policy, threshold, state, receipt, migration, dependency, engineering Arena or M6 file is changed. Left/right swipe and button semantics remain unchanged. The existing DOM-observer/portal mount is retained; it depends on the current consumer-card markup and has focused regression coverage.

Tests cover normalized metadata, observed Commons thumbnail URL shape, malformed/no results, upstream/timeout errors, unsafe URLs, rejected licenses, weak relevance, attribution, presentation classification, failed image load and stale-photo removal. Browser tests use explicitly labeled synthetic data to check mobile/keyboard controls, visible attribution, fallback and identical ALLOW behavior without media fields in evaluation requests. Existing engineering Arena coverage remains in the full Playwright suite. Synthetic tests do not claim live Qloo or actual-property identity proof.
